## 🐛 本次踩坑 / 注意事项

### 1. `WORKBUDDY_CREDENTIALS_DIR` / `WORKBUDDY_FEISHU_CRED_FILE` 仍是空变量
cron prompt 里说「env.json 的 feishu 凭证是占位值会失败」——**这次是成功的**。
`feishu_push_optimized.py` 实际走的是 `~/.minimax/credentials/general/feishu.json` fallback 路径,
凭证真实有效。下次跑不必再预期失败。

### 2. mmx 出图无 logo bug 未复现
10/13 踩坑 (生成图带 THE NORTH FACE 标识), 本次 5 张 prompt 都显式写了
`no text, no logo, no watermark, no lettering, no brand marks of any kind`,
视觉复核 product_1 / product_2 均为纯净产品图, 无品牌标识。

### 3. proxy 端口确认 7897 可用
`nc -z 127.0.0.1 7897` → OPEN; 7890 / 1087 closed。gen_images 脚本导出 `7897`, 与 10/14 一致。

### 4. db_export 与 step 12 版本号会不一致 (需注意)
`db_export.py` 自己算了一个 VERSION (`1792019100`) 并创建了 `v/1792019100/`,
之后 step 12 又用 `date +%s` 生成 `1792019122`, 产生**两个版本目录**。
两者内容 byte-identical (都从同一份 output/ 拷贝), 不影响 correctness, 但会多推 2 个目录。
→ **明天优化**: 让 db_export 支持读取外部传入的 VERSION, 或统一在 db_export 之后再做版本化。

### 5. `history.json` 路径
在 `history/history.json` (子目录), 不是根目录。cron prompt step 11 写的
`${TASK_XHS_DIR}/history.json` 路径不存在, `git add history.json` 会 fatal。
正确路径: `history/history.json`。

### 6. `.DS_Store` 被 git 跟踪
根目录 / output/ / v/ 下都有 `.DS_Store` 变更被误加进 commit。
→ **明天优化**: 考虑把 `.DS_Store` 加入 `.gitignore` 并 `git rm --cached`。
