## 🐛 本次发现并修复的 Bug

### Bug: 浅色主题导致卡片文字不可读
**现象**: 商品 1 主题色 `#F0E6D8`(浅米色, 匹配吹风机奶油白机身),
`compose_cards` 直接把 `p["color"]` 用作标题/小节标题/分隔线的填充色,
在纯白底(255,255,255)上渲染出来几乎看不见 —— 标题和亮点标题都是浅米色。

**根因**: `compose_cards_20261004.py` 起 `color` 既做**装饰色块底色**(白字, 需深)
又做**白底文字色**(需深), 没有对比度校验。历史 9 期选的 `color` 恰好都是
深蓝/深红/深绿等深色, 问题一直没暴露; 本期选到浅色才暴露。

**修复** (`compose_cards_20261007.py`): 新增两个亮度感知函数, 按 WCAG 相对亮度
分别给"白底文字"和"色块底色"设不同目标上限:
```python
def _lum(rgb): return 0.2126*r + 0.7152*g + 0.0722*b
def readable_on_white(hexstr, max_lum=140.0)  # 白底上的文字/线条 → 压到 lum<=140
def solid_fill(hexstr, max_lum=108.0)          # 白字压色块 → 压到 lum<=108
```
并做了**饱和度回补**: 纯缩放会把浅色压成灰泥, 所以先缩放到目标亮度,
若通道差 <30(近灰)则按 0.45 权重掺回原主题色, 再重新压一次亮度。
标题/分隔线/4 个小节标题改用 `ink`(=`readable_on_white`),
编号方块/标签 chips/底部价格条/顶部色条改用 `solid`(=`solid_fill`)。
**顶栏色条也一并处理**: 商品 1 顶栏原本是浅米色配白字编号"01", 同样不可读。

**验证**: 重新合成后 slice_1(浅色卡) 标题"徕芬 Laifen..."恢复深灰可读、
编号方块变深灰白字清晰; slice_5(饱和棕 #B5651D) 主题色基本不变, 无回归。
