## 🐛 Bug 发现与修复 (今日新增, 明天务必注意)

### 1. ⚠️ 代理 7897 已下线 — mmx 直连反而通

`gen_images_2026MMDD.sh` 里从 10/13 起一直挂着:
```bash
export HTTPS_PROXY=http://127.0.0.1:7897
```
今天实测 5 张图全部 `code: 6 / Network request failed`。
排查: `lsof -nP -iTCP -sTCP:LISTEN | grep 7897` → **无进程监听**;
`scutil --proxy` → System Proxy 全 0 (HTTPEnable=0)。

**修复**: 去掉两个 export 后直连 `api.minimaxi.com` 秒通, 5 张图一次过。
**结论**: 7897 是 10/13 当时的**临时**代理端口, 不是常驻。
**明天做法**: `gen_images_*.sh` 已改成不挂代理。万一再失败, 先 `lsof` 确认端口,
再试 `mmx config set --key proxy --value http://HOST:PORT` 或直接直连。

### 2. ⚠️ cloudimgs 上传后**文件名会被加时间戳**

第一次上传 (desc 还没修完时) 返回 `2026-10-16_product_1.jpg`;
desc 改完重新上传, 返回的却是 `2026-10-16_product_1_1792105526896_1.jpg`。

也就是说 **build 脚本里写死的稳定名 URL (`{IMG_BASE}_product_{id}.jpg`) 上传后就失效了** ——
landing page 会拉到第一版(旧文案)的图。

**修复**: 新写 `scripts/attach_cdn_urls_20261016.py`, 从 `uploaded_urls.json`
读**实际返回的 URL** 回填 data.json / vs-data.json, 并 assert 全部 https。
映射规则:
```
data.json    products[i]           -> product_{i+1}.jpg + product_slice_{i+1}.jpg
vs-data.json competitors[c] 第1项  -> product_{c+1}.jpg
vs-data.json hotProducts[i]       -> product_{i+1}.jpg
```
⚠️ `uploaded_urls.json` 的 name 是**本地相对路径** (`images/product_1.jpg`), 要 `.split('/')[-1]` 归一化。

**明天做法**: 步骤顺序必须是「上传 → attach_cdn_urls → schema 校验」,
**不要**先跑 attach 再上传。另外任何改动导致重新合成卡片, 都必须**重新上传 + 重新 attach**。

### 3. ⚠️ desc 字数超 150-200 上限

第一版 desc 写太长: [268, 279, 197, 215, 287], 5 个里 4 个超标。
卡片里「商品详情」区块是 `max_lines=7` 硬截断, 超长会导致详情被砍 + 留大片空白。
**修复**: 压缩到 [210, 209, 197, 210, 206], 关键数据点(销量/认证编号/推力)全部保留。
**明天做法**: build 脚本写完先跑一遍字数断言, 别等 schema 校验才发现。
