### 🐛 重要发现: git push 必须走本机代理 (今天踩坑)

**现象**: 按 cron prompt 里写的 `git -c http.proxy= -c https.proxy= push origin main` 绕过代理,
连续 2 次 `Recv failure: Operation timed out`,commit 卡在本地推不出去。

**根因**: 本机环境变量里有 `HTTP_PROXY=http://127.0.0.1:6696` / `HTTPS_PROXY` 同样指向 6696,
且该代理端口处于 OPEN 状态。cron prompt 里的 `-c http.proxy=` 是在**主动清空**这个可用代理,
所以直连 github.com 必然超时。对照实验:

| 方式 | 结果 |
|------|------|
| `curl --noproxy "*"` 直连 github.com | http_code=000 (15s 超时) |
| `curl` 走环境代理 6696 | http_code=200 (2.9s) |
| `git -c http.proxy= push` (清空代理) | Recv failure: Operation timed out |
| `git -c http.proxy=http://127.0.0.1:6696 push` | ✅ 成功 |

注意 `api.github.com` 直连能通 (200),只有 `github.com` 主站需要代理 —— 所以**只测 api
会误判成"网络正常"**,必须测 github.com 本身。

**正确写法**(下次 cron 直接用):
```bash
GIT_SSL_NO_VERIFY=1 git \
  -c http.proxy=http://127.0.0.1:6696 -c https.proxy=http://127.0.0.1:6696 \
  -c http.lowSpeedLimit=0 -c http.lowSpeedTime=999999 \
  -c http.postBuffer=524288000 \
  push origin main
```

⚠️ 顺带说明: `common.sh` 里的 `git_proxy_push()` 同样是清空代理的实现,
在这台机器上会一直失败,建议改成读 `HTTPS_PROXY` 环境变量。
