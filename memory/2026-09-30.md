## 🐛 Bug 发现与修复: 死代理导致飞书推送 100% 失败 (重要)

### 现象
```
python3 scripts/feishu_push_optimized.py output/2026-09-30 2026-09-30
→ urllib.error.URLError: <urlopen error [Errno 61] Connection refused>
```
prompt.md 里写的已知风险是"env.json 里 feishu.app_id/secret 仍是占位值,飞书推送会失败" — **这个描述已过时**。

### 真实根因
1. **凭证是真实有效的** — `~/.minimax/credentials/general/feishu.json` 里的 appId/appSecret 完整,
   `curl --noproxy '*'` 可正常换到 `tenant_access_token` (code=0, expire=7200)
2. **真正的问题是本机残留死代理 `127.0.0.1:6696`** (VPN 客户端未运行)
   - `curl` 不加 `--noproxy` → `Failed to connect to 127.0.0.1 port 6696`
   - Python `urllib.request.urlopen` 默认走环境/系统代理 → `[Errno 61] Connection refused`
3. 所以飞书推送失败**跟凭证无关**,是网络代理问题。历史每天的"飞书失败"很可能都是同一个原因,
   而非 prompt 里说的占位凭证。

### 修复
`scripts/feishu_push_optimized.py` 加全局 bypass opener:
```python
_OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}))

def _urlopen(req, timeout):
    return _OPENER.open(req, timeout=timeout)
```
3 处 `urllib.request.urlopen(` 全部替换为 `_urlopen(`
(get_token / upload_image / POST card)。

### 修复后效果
```
✅ 凭证有效,开始推送 2026-09-30 的素材到飞书...
  [1/4] 获取 tenant_access_token ... ✅
  [2/4] 上传 10 张图 ... ✅ 全部 img_key 拿到
  [3/4] 构建 interactive card ... ✅ (10/10 张图)
  [4/4] POST 到飞书 webhook ... ✅ 飞书推送成功! StatusCode=0
```
**这是本任务首次飞书推送真正成功**（此前因死代理每日静默失败）。

⚠️ 副作用: 3 处 `urlopen` 出现在 upload 和 upload_cloudimgs 的同类模式里,
若将来该机代理恢复且需要走代理,需把这个 bypass 改成可配置项。
