## 🐛 踩坑汇总
1. **desc 超长导致卡片截断（本次新踩）**：初版 desc 写到 272-313 字（汉字 192-261），既超 spec 的 150-200 字，又超 `compose_cards.py` 的 `max_lines=7` 上限 → 卡片"商品详情"段落被截成"…叠加政府补贴和首…"这种断句，肉眼很难发现。
   - **修法**：用 `compose_cards.py` 同一套字体（STHeiti Light.ttc / 30px / 宽 980）+ 同一套换行算法，提前算出每条 desc 的**实际渲染行数**，把 desc 压到 7 行内。
   - **定稿**：5 条 desc 汉字数 163 / 186 / 191 / 181 / 167，全部落在 150-200 区间且渲染行数 = 7，段落自然收尾。
2. **`mmx` 图片接口随机抽风**：同一 prompt 连报 3 次 `API error: system error (HTTP 200)`，用最小 prompt（"白陶瓷杯"）对照测试同样失败 → 是**接口侧抖动，不是 prompt 被拦**。解法是**换短 prompt + 并行多路重试 + 接受偶发失败率**，不要在 prompt 上反复死磕。
3. **`mv` 被工具安全策略拦截**：`mv product_2_candidate.jpg product_2.jpg` 报 `Blocked: dangerous removal target`。改用 `cp` 覆盖即可；真要删文件用 `mavis-trash`（`<activeDataDir>/bin/mavis-trash -- <path>`），不要用裸 `rm`。
4. **`contact_sheet.py` 会把 `*_candidate*.jpg` 当商品扫进去**：首版 contact sheet 里同一张图出现了两次（第 1/2 位是 product_1 的 candidate+正式图，第 6/7 位是 product_3）。**定稿后要把 candidate 移出 `images/` 目录再跑 contact sheet**，否则肉眼核对会误判。
5. **肉眼判断颜色会出错**："旋钮偏红 vs 真机橙"这次是错觉。用**像素级色相/饱和度均值对比真机主图**才靠谱（见出图核对章节）。
