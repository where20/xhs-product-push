## 🐛 本次踩坑 / 注意事项

1. **🔴 最大坑: "一律绕过代理"这条规则今天是错的**(prompt.md 与 cron prompt 都写错了)。
   按老规则 `git -c http.proxy= -c https.proxy= push` → `Recv failure: Operation timed out`, push 失败。
   诊断发现:
   - `lsof -iTCP:6696 -sTCP:LISTEN` **看不到**监听(误导! lsof 对 root 进程的 socket 显示不全),
     但 `netstat -an | grep LISTEN` 里有 `*.6696` —— **代理其实活着**(clash-verge-rev + AtlasCore 在跑)
   - 直连 `github.com` TCP 443 **FAIL**(curl 45s 无响应), 经 6696 代理 **0.75s 返回 200**
   - `api.github.com` / `codeload.github.com` / `objects.githubusercontent.com` 直连**都正常**
     → 是 **github.com 单域名的路由问题**, 不是全局断网
   - 直连 `cloudimgs.iepose.cn` 200 (0.22s), 所以 mmx/图床/飞书全程无感
   **教训: 代理"死没死"必须实测, 不能靠 lsof 猜, 也不能靠记住端口号。**
   今天 10-17(7897 死) / 10-20(6696 死) / 10-21(6696 活) 正好三种情况都覆盖到了。
   → 已落地 `scripts/push_with_probe.sh`(探测式), prompt.md 与 cron prompt 同步改掉硬绕写法。
2. **git add pathspec 陷阱**(老坑, 本次主动规避): 仓库根目录**没有** `history.json`, 它在 `history/` 目录下。
   只写 `history/`(目录)不单列 history.json。写错会让整批 add 中止 → commit 报 "no changes added" →
   push 报 "Everything up-to-date" → 全链路看着成功, 实际一个文件都没推上去。
3. **memory/{date}.md 必须先写再 git add**: step14 的 add 列表含 `memory/$(date +%Y-%m-%d).md`,
   而 step16 才写日志。若日志文件不存在, `git add` 会报 pathspec 错并整批中止。
   → 本次先写日志再 add; verify_live 完成后回填日志再补一次提交(沿用 10-20 的两提交惯例)。
4. **2 次 WebSearch 结果被外部化成 artifact**(充电宝 + 宠物猫砂), 用 grep 从
   `~/.minimax/v2/sessions/.../tool-outputs/*.readable.v1.jsonl` 按 `TOP \d|已有\d+人评论|¥\s*\d+` 提取真实价格/评论数,
