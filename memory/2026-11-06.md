### 🐛 修复：`push_with_probe.sh` 误把「拒绝」判成「成功」（本次真 bug，已修）

**Bug**：远端拒绝行本身含 `main -> main` 字样：
```
 ! [remote rejected] main -> main (fatal error in commit_refs_rules
```
老判据 `grep -qE "${BRANCH} -> ${BRANCH}"` 会命中这行 → 打印「✅ push 确认成功」→ **exit 0**。
**危害比 push 失败本身更大**：脚本谎报成功，整条 cron 流水线以为已发布，不会重试、不会告警。

**修复**（`scripts/push_with_probe.sh`）：**先判拒绝，再判成功**，且成功行必须匹配行首的
SHA 区间 / `[new branch]` 格式：
```bash
if grep -qE "remote rejected|! \[rejected\]|\[rejected\]|fatal error|error: failed to push" /tmp/xhs_push.log; then
  echo "❌ push 被远端拒绝 ... 判定为未推送成功" >&2; exit 1
fi
if grep -qE "^[[:space:]]*[0-9a-f]{7,}\.\.[0-9a-f]{7,}[[:space:]]+${BRANCH} -> ${BRANCH}|\*[[:space:]]+\[new branch\]" /tmp/xhs_push.log; then
  echo "✅ push 确认成功"; exit 0
fi
```
**已用真实失败日志 + 成功日志双向验证**：失败日志 → 正确判失败（不再误报）；成功日志 → 正确判成功。

1. **`push_with_probe.sh` 会把「远端拒绝」误判成「成功」（本次真 bug，已修）**：
   拒绝行 `! [remote rejected] main -> main (...)` 里含 `main -> main`，被老判据的 grep 命中 → 脚本 exit 0 谎报成功。
   **危害 > push 失败本身**：流水线以为已发布就不会重试、不会告警。已改成「先判拒绝、再判成功」并双向验证。
   ⚠️ **以后 push 后必须 `git ls-remote origin main` 核一次远端 SHA**，别只信脚本输出。
2. **GitHub 瞬时 `fatal error in commit_refs_rules`**：今天真实遇到，约 5-8 分钟自愈。排除法定位路径见上文排查链。
   **应对：不要改提交、不要 force push、不要重建 .git**（网上「rm -rf .git + rm -rf ~/.ssh」是暴力偏方，会毁本地历史），**等几分钟重试即可**。
3. **外链不能凭记忆写**：`taouq.com` 天猫在售页当场 403 被闸门拦下。**所有 links/sources 一律先过 `verify_links.py`**。
4. **smzdm 移动域 `ju` 榜是空壳**：`m.smzdm.com/ju/*` 209 字节；必须用 `www.smzdm.com/ju/*`（104KB）。移动域只有 `p/{id}` 可用。
5. **JD 榜单页价格恒空**（`price-rmb` JS 渲染），且**内容按关键词轮换** → 同一页重试 8-15 次仍可能轮不到目标 SKU；轮不到就换榜页（猫粮 4 个页返回 size=0 也是轮换现象之一）。
6. **单榜页覆盖不全**：瑜伽垫 ju 榜只出特步一家 → 用社区实测文 `post.m.smzdm.com/p/{id}` 补齐 4 个竞品品牌。
7. **子命令成功 ≠ 整条命令成功**：`gen_images.sh` 5/5 成功却因我后写的 `ls` 路径错误返回 1。**以子命令输出为准**。
8. **`gh repo create` 报 GraphQL 错误不代表账号挂了**：GraphQL 与 REST/gits 各自独立故障面，排查时**分开测**（本次 REST 全通、GraphQL 偶发错）。
